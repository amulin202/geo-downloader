# GeoD 多层注记内存修复（2026-10-12）

基于 v3.6.12 后的 main，在 `codex/geod-overlay-memory` 分支实现。尚未打包或发布新版。

## 用户反馈与已确认的问题

反馈任务为 z15 主图源 336,660 张瓦片、三层注记；电脑为 Windows 10、16 GB RAM。参数截图为原始瓦片目录、620 × 543。没有用户崩溃日志，不能确认其进程终止原因；以下内存累积问题已通过代码及模拟实验确认。

旧实现将缓存命中的每张主瓦片和注记存为 `Arc<Vec<u8>>`，又将全部合成 PNG 保留在 `composites_to_apply` 中。原始瓦片目录的预估还错误地使用整幅栅格画布公式。

## 实现

- 下载器的批量缓存命中、浏览补齐、并发缓存命中、重试缓存命中均逐张写入任务目录，只返回文件路径。
- 缓存写盘使用临时文件和重命名；失败为终止错误，避免磁盘故障被当成注记缺失跳过。
- 合成工作每批最多 64 个坐标，在独立工作线程逐张解码、叠加、直接编码到文件。批次只返回路径，导出不保留整批 PNG 字节。
- 合成结果放在 `__composited/x/y.png`，保留原始输入，重启恢复从原始输入重新合成，避免重复叠加。
- 合成阶段有计数进度，每批响应暂停、每张响应取消。缓存扫描也响应暂停和取消。
- 原始瓦片、MBTiles、GeoPackage 使用逐瓦片工作集预估：128 MiB 固定缓冲加每个瓦片约 1 KiB 路径索引。估计值不是应用总内存承诺。620 × 543 对应约 457 MiB；阈值仍仅提示，可自定义或不限。

## 验证

`cargo test --lib`：152 项通过。新增测试覆盖三层顺序、透明度、不同尺寸、写盘失败、缓存落盘、中途取消、暂停恢复、暂停时取消、中断后从原始输入重试、原始瓦片目录导出，以及截图规模的预估。

模拟实验：256 × 256 合成影像，主 JPEG 46,245 B、三层注记总计 6,319 B，合成 PNG 215,087 B。运行 `cargo run --example overlay_memory_probe -- disk` 可复验生产合成路径，512 张输出逐一与旧算法结果比较，全部一致。

| 保留输出数 | 旧内存输出：进程私有内存增量 | 新磁盘输出：进程私有内存增量 |
|---|---:|---:|
| 128 | 53.13 MiB | 0.54 MiB |
| 256 | 106.25 MiB | 0.54 MiB |
| 512 | 212.48 MiB | 0.46 MiB |

以上是模拟样本进程的内存读数，不是用户 336,660 张任务的整批实测，也不是整个桌面应用的内存读数。文件路径和任务索引仍随瓦片数量增长；合成 PNG 会占用磁盘空间，额外磁盘读写是限制内存的代价。

`git diff --check` 通过。当前在运行的 GeoD 进程未重启，仍须加载新构建才能使用修复。
